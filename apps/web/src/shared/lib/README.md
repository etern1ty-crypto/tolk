# Работа с сервером

Всё общение с бэкендом идёт через `api.ts`. Прямой `fetch` в компонентах —
признак того, что что-то пошло не туда.

## Запрос

```ts
import { fetchApi } from '../../shared/lib/api';

const chats = await fetchApi('/chats', {}, token);
const post  = await fetchApi('/posts', { method: 'POST', body: JSON.stringify({ text }) }, token);
```

Заголовки `Content-Type` и `Authorization` проставляются сами. При неуспешном
ответе бросается ошибка, у которой **код лежит на объекте**, а не в тексте:

```ts
try {
  await fetchApi('/me', {}, token);
} catch (e: any) {
  if (e.status === 401) logout();   // так, а не e.message.includes('401')
}
```

Это не придирка. Раньше проверяли текст, сервер отвечал словом
«Unauthorized», совпадения не было никогда — и протухшая сессия не выходила, а
бесконечно перезапрашивала `/me`.

## Загрузка файла

Одна функция на все случаи. Три шага — регистрация, передача байтов,
подтверждение — внутри, и любой сбойный шаг бросает ошибку.

```ts
import { uploadFile } from '../../shared/lib/api';
import { prepareImage } from '../../shared/lib/imagePrep';

const prepared = await prepareImage(file, 'avatar');
const { url } = await uploadFile(prepared, { kind: 'image', purpose: 'avatar' }, token);
```

**`kind`** — что это по типу: `image` · `voice` · `circle` · `file`.
Определяет проверки MIME на сервере.

**`purpose`** — подо что: `avatar` · `banner` · `wallpaper` · `post` ·
`message` · `voice` · `circle`. Определяет, **останется ли файл на диске**:
аватарки, обложки и фоны чатов в облако не уходят никогда, потому что нужны на
каждом экране (см. `apps/gateway/offload.go`). Ошибиться здесь — значит
отправить аватарку в Google Drive и получить задержку при каждой отрисовке
списка чатов.

Картинки перед загрузкой прогонять через `prepareImage`: она приводит размер к
тому, как изображение показывают, и снимает EXIF — в снимке с телефона иначе
уедут координаты съёмки, а аватарка публична.

## Куда идут запросы

По умолчанию — на тот же origin, что и страница. Так быстрее: запросы несут
`Authorization` и JSON, а к другому имени такие требуют предварительного
запроса CORS, то есть лишнего круга до сервера на каждый новый путь.

Поддомены подняты и работают:

| Имя | Для чего |
|---|---|
| `api.tolkmessenger.ru` | тот же шлюз отдельным именем |
| `ws.tolkmessenger.ru` | веб-сокет |

Они нужны тому, у кого нет CORS, — **нативному приложению**. Переключаются
переменными сборки, править код не требуется:

```
# apps/web/.env.production
VITE_API_URL=https://api.tolkmessenger.ru
VITE_WS_URL=wss://ws.tolkmessenger.ru
```

Веб-клиенту это включать не стоит: он ничего не выиграет и заплатит
предварительным запросом. Если всё же включаете — origin должен быть в
`CORS_ORIGINS` на сервере, иначе сокет примет рукопожатие и тут же закроет
соединение с кодом 1008. Именно так и случилось при переезде на новый домен:
в `.env` остался прежний адрес, и живая доставка молча умерла.

## Чего избегать

- **`fetch` мимо `api.ts`** в компонентах.
- **Своей копии трёхшаговой загрузки.** Их было семь, они разошлись, и одна
  перестала проверять результат передачи: запись о файле создавалась, байтов за
  ней не было.
- **Разбора кода ответа из текста ошибки.**
